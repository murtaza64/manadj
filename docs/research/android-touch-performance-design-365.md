# Native Android performance cockpit — design support for #365

**Status:** design hypotheses, not user-tested; no Android implementation or landing. The existing browser phone prototypes are not the target. Prototype native Compose touch interactions before choosing audio/runtime architecture. Scope the first phone proof to Decks A/B; preserve explicit access planning for C/D rather than silently mapping desktop keyboard's left/right focus to A/B forever.

## Recommendation and choices

Prototype **Concept 1: twin-deck cockpit** first. Both decks' transport, cue, track status, waveform and the crossfader remain on-screen while a single *active-deck* workspace changes between PADS / JUMP / LOOP / MIX / FX. A/B chip changes workspace ownership only; it must never swap, stop, or load audio. A cyan `#00e5ff`, B pink `#ff2d95`; use the existing neutral-gray, square, Ubuntu Mono vocabulary and semantic tokens from `DESIGN.md`, not djay's styling. Distinguish deck selection (outline), playing (filled transport), PFL (headphone icon), and currently audible deck (meter); do not use one color fill to imply all four.

Decide before building: (1) should C/D be an explicit deck pair selector in a later phone prototype, or is A/B the intentional phone scope? (2) Does holding CUE mean the existing CDJ-style momentary cue, including release/cancel, or a toggle? Recommend preserve momentary. (3) Should one-finger swipe on a waveform seek, nudge, or scrub? Recommend waveform pan/scrub only after an explicit SCRUB handle/mode; swipes on control tiles always adjust their control. (4) What is the minimum supported *usable* height after real status/navigation insets and display/font scaling? See 360×640 fallback below. (5) Is FX a master/targeted Beat FX control, per-deck instant FX, or both? Recommend a shared Beat FX target row plus active-deck instant FX; never silently retarget active effects on A/B selection.

Recompute available height and choose compact composition, never vertical page scrolling. Reserve keyboard/IME for a separate, non-performance library picker; never shrink the live cockpit behind IME.

Quantize grid and beatjump size shown in tool bank status, not hidden in a long press.

### Structural alternatives / trade-offs (hypotheses)

1. **Twin-deck cockpit (recommended):** vertical symmetric deck lanes in portrait; horizontal A / bank / B in landscape. Explicit A/B selection for tools, but either deck's PLAY/CUE remains directly playable. Highest confidence that unselected-deck state is legible; workspace has less vertical room on short screens.
2. **Deck focus + safety rail:** large active deck, smaller always-visible other-deck transport/status; tap its A/B badge to promote it. More waveform/scrub precision on focus deck, but risks hiding other-deck pads behind a focus switch and visual hierarchy making other deck feel inactive. The other deck's CUE/PLAY must still be 48dp and usable.
3. **Dual split + central instrument:** A and B vertical strips persist at both edges with a large centered instrument area, crossfade full width at bottom. Favors two-thumb performance and bigger XY FX field in landscape; weakest on 360dp portrait because deck strips compete with instrument width. Reject portrait if deck hit targets cannot fit.

## Tool bank behavior (same contract in each concept)

- **Always visible**: both track labels + transport playing/paused/ready, A/B CUE and PLAY, current loop and PFL indicators, master/crossfade position and output meter; rail stays put when changing banks. A/B status indicates other-deck audio and its live FX/loop activity. PLAY tap toggles; CUE touch-down previews/returns per current cue mode, touch-up/cancel releases. If current cue mode changes behavior, label it.
- **PADS:** 8 hot cues across two 4-pad rows on 800dp; compact optionally `1–4 / 5–8` pages; slot numbers and user colors visible. Tap triggers, press-hold previews if applicable, edit mode explicit `SET / CLEAR` so holding to tweak a mix cannot delete a cue. Provide selected-deck badge inside bank; loaded/empty/preview state distinct. Include stem controls as a **second named page** if phone scope requires desktop stem kills, not phantom unlabeled pad modes.
- **JUMP:** ±1/2/4/8/16/32 beat size selector plus 48dp back/forward action; visual selected size; NUDGE −/+ momentary pair and tempo MATCH/SYNC/KEY LOCK/PITCH controls in clearly labeled secondary row/page. Direct jump needs no screen-relative gesture. Waveform drag only in a labeled scrub mode to avoid accidental seek.
- **LOOP:** one-tap ON/OFF, length halve/double and explicit IN/OUT, ROLL momentary and current length visible. Changing size while active resizes loop; while inactive changes next loop length; never reuse JUMP arrows without labeling. Loop-bracket state visible on both deck summaries.
- **MIX:** first page active-deck channel VOL, FILTER, LOW, MID, HIGH in **large labeled 48dp+ control tiles** (not four skinny sliders); second page TRIM, PFL, PITCH if space forces it. Neutral 0.5 for EQ/filter, fader end positions 0/1. A tap on a tile does *not* jump value; drag vertically, hold for precision; tap dedicated neutral marker to center. Crossfader remains in pinned rail for two-deck mixes, not hidden in MIX. FX effect type, length, depth and target A/B/MST visible together on FX page; if FX is already active, selection of a different deck must not retarget it.
- **FX:** named effect, ON/OFF, length halves/doubles, depth large tile, explicit target chips A/B/MST, plus 2D XY surface when chosen; dragging within XY space controls two labeled parameters and releases only momentary effects. For latch effects, explicit ON state. An independent quick FX pad may remain in the active bank; its trigger must not mask CUE/PLAY. Confirm display of wet/dry and tail state after FX off. Sessions/Set planning, browsing, deep beatgrid edits and metadata editing are separate screens, not squeezed into performance.

## Touch contract to prototype

- Minimum **48×48dp interactive hit box**, ≥8dp between neighboring destructive pad actions. Visual mark may be smaller, hit rect not. Avoid accidental system-back/edge swipe: keep fader origin ≥24dp inward from gesture-nav edges; route system Back to close precision overlay first, then bank/screen. No page-scroll recognizer on live surface.
- Compact knob tile **touch-down fixes** `startValue`, pointer ID and coordinates; moving vertically changes `clamp(startValue − (currentY − startY)/sensitivity)`; horizontal travel may be offered for XY FX only. **Never derive value from absolute touch location**: touching an off-center filter does not jump. Gesture owns pointer after down inside tile, even when finger moves across tabs/decks and beyond original bounds, until up/cancel. Visual rail remains stationary as finger travels screen-relative distance.
- Hold stationary for ~350ms (<6dp drift) opens full-screen precision overlay; same pointer continues controlling the same value without a discontinuity. Show label, numerical/current value and center marker **≥72dp above the finger**, clamped away from top edge; large vertical track with ghost of touch-down value and center. In overlay use 3–4× finer gain, seeded from *current* value and *current* finger coordinate (no gain jump). Immediate drag without waiting uses coarse gain, optional horizontal drift >32dp reduces gain only while still captured; never steals a pad/cue interaction. Disable parent page swipe and nested scroll during control gesture.
- Center detent: bipolar EQ/filter 0.5 with a visible notch and haptic on first entry; crossing requires another ~8dp or movement out-and-back, not a permanently stuck zone. Crossfader center and ends get visible ticks; crossfader stays direct absolute drag **only if touched on handle**; tapping empty rail doesn't jump, touching rail background can use relative drag. Double tap neutral only on continuous tiles (not PLAY/CUE); an explicit `RESET` affordance in precision overlay makes reset discoverable; pitch reset to 0%, fader reset requires deliberate confirmation if it would become audible. Accessibility alternate step −/+ and verbal value for every tile.
- Each pointer independently owns exactly one originating control. Second pointer may play the other deck, cue, crossfade, or press FX while first finger holds a filter; do not cancel pointer 1 when pointer 2 arrives. On bank/deck switch with an active gesture, defer switch until release or show pending selection—never retarget mid-gesture. `UP` commits continuous control and releases momentary cue/nudge/roll/FX; `CANCEL` or lifecycle loss releases momentary actions immediately and restores continuous control to touch-down value with a short safe ramp (validate audible behavior). Clear capture after cancellation; new gesture must begin a new baseline. All hit testing is by touch-down target, not the finger's current bounds. Haptic/tick feedback is supplemental, not a substitute for visual values.

## Prior art, facts vs hypotheses

- **Verified existing manadj virtual keyboard controls (direct inspiration):** [`DeckKeys.tsx:37–108,109–155`](../../frontend/src/components/performance/DeckKeys.tsx) starts a floating feedback view on held per-deck knob/fader keys; while held, dominant-axis mouse movement (`dx` or `−dy`) advances the *current* mixer value by `delta/360` (not an absolute cursor position). It releases on keyup and guards a ≤250ms/≤3px second tap within 300ms for filter reset to 0, EQ cut/neutral and VOL cut/full. [`keyboardPointer.ts:78–197,297–375`](../../frontend/src/components/performance/keyboardPointer.ts) anchors the popup at last unlocked mouse position, requests pointer lock, renders simultaneous held-control knob/fader values/ghosts and cancels on Escape, lost lock, blur or hidden page; [`keyboardPointer.css`](../../frontend/src/components/performance/keyboardPointer.css) styles this transient overlay. [`mouseControl.ts:1–33`](../../frontend/src/components/performance/mouseControl.ts) uses a 360px full sweep and a center latch: continuous motion sticks at center, a 160ms movement pause allows departure, external changes or a new hold clear the latch; see [`mouseControl.test.ts`](../../frontend/src/components/performance/mouseControl.test.ts) and [`keyboardPointer.test.ts`](../../frontend/src/components/performance/keyboardPointer.test.ts). [`BeatFxKeys.tsx:21–69`](../../frontend/src/components/performance/BeatFxKeys.tsx) shares this popup for depth −1..+1, displaying DRY/BAL/WET; its **code** resets double-tap to −1 DRY, despite the file's header saying center. Distinct on-screen [`MixerStrip.tsx:83–120`](../../frontend/src/components/performance/MixerStrip.tsx) knob captures value/Y at touch-down for a **150px** relative drag; `HFader` at lines 202–258 maps initial X **absolutely** (jumps), which should *not* be carried to a compact phone rail. Port the relative baseline, legible live feedback, center latch and lifecycle; pointer-lock API is desktop-only. The suggested 350ms touch-hold to reveal an enlarged, finger-offset **precision** overlay is **new**, not something the existing keyboard popup already does; existing popup appears immediately on keydown and has no coarse/fine switch.

Inspect its Android phone image and tablet image for prioritization, **not** geometry, artwork or exact control placement to copy. The product's 8-loop looper is an example of grouping high-density features behind a dedicated tool, not evidence our layout works.

## Falsification checklist for a native Compose throwaway

Run at 360×800dp, 360×640dp, 800×360dp with real window insets, 1.3× font scale, gesture navigation, and two fingers on hardware or emulator multi-touch. Observe: no page scroll, clipping or 48dp violations; touch filter at extremes without audible jump; start 48dp filter tile and swipe ~200dp beyond it while control continues; hold opens offset value without finger covering it; crossing center settles at 0.5 and resets; keep A's filter engaged while B CUE and crossfader operate; lift/cancel during CUE/ROLL/Nudge/FX and verify no stuck actuation; drag crossfader at center while other finger plays pad; switch bank/deck during capture without retarget; rotate during gesture and ensure cancel; both transports and crossfade remain reachable in every bank; landscape preserves playable pads rather than compressing portrait. Compare the three concepts on first-action time and wrong-deck/wrong-control events; do not treat the reference app's marketing screenshot as a usability test.
