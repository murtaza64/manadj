# Android uses one native PCM mixer and output clock

The first real Android slice uses platform decoding off-thread and one Oboe PCM output/mixer, with stable A–D identities. The native performance layouts, and future Session/Conductor clients, submit commands and observe the same engine snapshots; Compose does not advance playback time. Independent Media3 players would make shared-clock mixing and sample-domain transport a later replacement rather than an incremental extension.

The native module owns bounded PCM storage, load identities, the transport (relocation) counter, callback state and accepted/applied command IDs. Cue and hot-cue decisions run on the audio callback against authoritative deck state, mirroring desktop `transport.ts`. The app owns persisted document grants, metadata, selection and Android audio-focus/service lifetime. A source is READY only after priming; output-open errors remain separate from source readiness. Source replacement or relocation must never associate old PCM or clock state with a new track identity or position.

This is the initial parity candidate from [#367](https://github.com/murtaza64/manadj/issues/367), implemented through [#369](https://github.com/murtaza64/manadj/issues/369) and [#370](https://github.com/murtaza64/manadj/issues/370). v1 layouts are L1 (portrait workspace) and L3 (dense landscape); the mirrored dual-mixer layout is deprecated (2026-10-13). Unsupported DSP, grid/sync and scratch controls remain explicitly unavailable; waveform analysis can be pending, never fabricated for selected media. Physical-device latency and later stretch/FX/headphone-output choices remain unproven. The throwaway #365 change stays separate.
