# Native audio module (#370)

Android library `android/audio-engine`, namespace `dev.manadj.audio`, included by the root `android/` build. Oboe 1.11.0 ([release](https://github.com/google/oboe/releases/tag/1.11.0)), NDK `27.0.12077973`.

## API

- `load(deck, sourceId, descriptor)`: duplicates the caller's descriptor (must be seekable), queues `Prepare`, starts the deck's decode worker. Receipt = queued.
- `submit(AudioCommand)`: one seam for UI, Session replay and future Conductor. Cue/hot-cue gating and relocations are decided on the audio callback against authoritative deck state (desktop `transport.ts` semantics); receipts mean queued, `appliedCommandId` means applied.
- `schedule(atFrame, command, tag)` (+ batch forms, `cancelScheduled(tag)`, capability `schedule`): applies the op at engine output frame `atFrame` (`EngineSnapshot.outputFrames` counter). The callback splits its buffer at every due frame and applies in (frame, submission) order, so the op lands on that sample; deck positions integrate exactly between ops (error < 1 frame). Past frames apply at the next callback start and count in `EngineSnapshot.lateOps`; `scheduledOps` = pending. Queue 4096, pending 8192; scheduled `SetFilter` keeps its own target. Sample-exact relocations need the in-memory track (`fullyDecoded`).
- `snapshot()`: output-frame clock and per-deck source position, cue, hot cues, `filling` (relocation refill in progress: silent, clock held), `atEnd`. Compose does not advance playback time.
- `SetCrossfade`: -1 = A only, 0 = both unity, +1 = B only.
- `close()` off the main thread. Unsupported stems/scratch/key-lock/sync are absent from `supportedCapabilities`.

## Model

- Four 65536-frame stereo float rings (2 MiB). Sources decode incrementally (MediaExtractor + MediaCodec, float output when the decoder allows; raw 8/16/24/32-bit/float WAV).
- Every relocation (load, seek, cue return, hot-cue jump) bumps the deck's `transport` on the callback. The deck worker seeks its decoder in place (extractor seek + codec flush), resets the ring (worker-owned indices), refills and publishes; the callback renders only `ring == transport`, so stale PCM is never audible.
- Load status is `(loadId << 2) | state`; READY/ERROR are CASes a superseded load cannot win.
- In-memory track: after Prepare applies, a second decoder per deck fills the whole track into native memory (int16 stereo, ~10 MB per minute at 44.1 kHz; skipped when MemAvailable would drop under 768 MB). Inside the decoded region every relocation (seek, cue, hot cue, beat jump, loop wrap) is exact to the sub-frame and immediate — position = render position + displacement, the old audio crossfades out (5 ms) — and the ring/heads are bypassed; outside it (still decoding) the streaming ring serves, and leaving the region resyncs the ring. Snapshot: `decodedSeconds`, `fullyDecoded`, `fromMemory`.
- Quantize (desktop `transport.ts`/`quantize.ts`, constant grid): cue placement (stopped, off-cue CUE) and hot-cue set snap to the nearest beat; a hot-cue trigger while playing lands at the cue's beat plus the playhead's signed beat phase; loop engage snaps. Gridless: exact. Quantized launch (desktop `launchStart`/`crossDeckLaunchTarget`, on the callback): a paused deck's Play / Cue-hold / Hot-cue-hold with Quantize on and another deck playing with a grid (nearest effective tempo, half/double folded; a Sync Group member only references in-lock members via `SetSyncMembers`; the launching deck needs a grid) aligns to that deck's nearest beat — Δ > 0 holds silent and starts on the beat's frame (`DeckSnapshot.launchFrame`), Δ ≤ 0 starts now |Δ|·rate ahead. Frame-stamped (scheduled) ops never launch-quantize (replay is exact).
- Output clock: `EngineSnapshot.clockFrame` (engine frame of the deck positions) + `presentedFrame`/`presentedNanos` (Oboe timestamp, System.nanoTime domain); `audibleSeconds(deck, nanoTime)` extrapolates the heard position for smooth playheads (phone: ~13 ms behind the render position, monotonic).
- Key lock (`SetKeyLock`, capability `key-lock`; desktop `deckSourceProcessor.ts`): Signalsmith Stretch (vendored in `third_party/`, the desktop's 1.3.2 build) in the desktop window model — every block refills an input window ending at playhead + rate × outputLatency + inputLatency from the in-memory track (loop-folded), `seek`, then `process`; a warm-primed reset on every start/relocation; split computation so each callback carries an even share. Non-48 kHz sources are read at the output rate and pitch-corrected by `setTransposeFactor(src/out)`. Without the in-memory track at the playhead, the deck resamples (pitch follows tempo; `DeckSnapshot.keyLockActive` false). Tails/crossfades render via resample, as on desktop. Cost (callback CPU time, M-series host; the phone is ~3x slower): ~45 µs per key-locked deck median, 4 decks p50 176 / p99 506 / max ~620 µs per 96-frame block — 2 decks fit the phone's 2 ms comfortably, 4 is marginal. Phone check: `PlaybackService` logs callback max/mean/near-misses every 10 s while playing (`adb logcat -s manadj-bench`). Native code builds at -O3 in every variant.
- Filter default: the desktop's shipped `manadj-filter-settings` (resonance 10.5, compensation 0.1) until the app applies the synced value; the TS code fallback (17 / 0.85) is ~12 dB quieter just off center.
- Pre-decoded heads: a second decoder per deck keeps 8192 frames at each hot cue and the main cue. A cue/hot-cue relocation whose head matches plays from it instantly; the ring refills from the head's last frame and the callback hands off sample-continuously. Heads being played are busy (worker cannot overwrite).
- Callback: no locks, allocation or I/O. ~5 ms fade-in on every start; every pause/stop/relocation captures a short tail of the old audio and crossfades it out (no hard cuts). Seeks without a head still have a ~10–20 ms silent refill after the fade.
- Channel strip (desktop parity, `Dsp.h`): trim → 3-band isolator EQ (LR4 crossovers 250 / 2500 Hz, knob .5 = 0 dB, 1 = +6 dB, 0 = kill; `SetEq`) → sweep filter (all desktop models — Original 12 dB, Resonant 12/24 dB, Steep 48 dB, Twin peak — with every FilterSettings parameter incl. drive and trim, `SetFilterSettings` live and click-free (model changes cross-fade between two branch banks); default `res24`; `SetFilter` -1..1; `filterResponseDb` = desktop sweepResponseDb, verified against values exported from the TS in `src/test/cpp/FilterCases.inc` via `src/test/tools/export-filter-cases.ts` (`bun run`)) → fader/crossfader to master, and pre-fader to cue. Filter targets (peak search) are computed on the submitting thread. 4 decks with EQ + filter: ~115 µs per 96-frame callback on the phone (2 ms budget).
- Grid / jumps / loops (desktop `beatjump.ts`, `loop.ts`, `transport.ts`): `SetGrid(bpm, anchor)` constant-tempo grid (local files: ID3 TBPM anchored at 0 s; library grids from #372). `BeatJump(beats)` is a relative displacement (gridless: 120 BPM) that carries an active loop with it. `LoopToggle`/`LoopPreset`/`LoopResize` engage at the playhead (nearest beat under `SetQuantize`), 1/8..128 beats, resize anchored at the start (a stranded playhead folds back in), absolute relocations (seek, cue, hot cue) cancel the loop; gridless tracks: engage is inert. The callback wraps at the loop end within a block, playing the loop start from its pre-decoded head (slot 9) with the sub-frame overshoot carried over, crossfaded like any relocation.
- Beat FX (desktop `beatFx.ts`, `beatFxRepeatKernel.ts`, `mixer.ts` section; `BeatFx.h`): one central section (`SetBeatFx(effect, target, on, depth, beats, held)`, written whole) over five inserts — one per deck post-fader/pre-crossfader, one on master after the deck sum (the cue blend hears it). ECHO / LOW CUT ECHO (300 Hz high-pass inside the loop) / REVERB / FLANGER are parallel returns over the dry path (depth -1 dry … 0 both unity … +1 wet); TRANS / ROLL replace the dry signal in series ahead of them (linear crossfade), phase-locked to the clocking deck's grid. Echo: 50 % feedback through the desktop tanh curve (4097-point table), delay = beats × deck beat seconds (grid × pitch/bend; gridless keeps the last known, default 120 BPM), retargets glide over 0.25 s; LCE and ECHO share one loop. Flanger: 3 ms ± 1 ms sine sweep, 35 % feedback, one LFO cycle per `beats` bars. MST follows the last deck target's tempo. Engage/disengage ramps 50 ms; turning an effect off closes its send so tails ring out; an insert idles (no DSP) once its tails die. Deviation: REVERB is an 8-line FDN (2.5 s RT60, 12 kHz damping, unit-energy impulse response) instead of the desktop 2.5 s noise convolution; no settings panel (desktop defaults). Memory: ~7.7 MB per insert (10 s echo line + 10 s ROLL ring at 48 kHz), ~38 MB total. Phone cost per sounding insert: echo ~36 µs, reverb/roll ~75 µs per 96-frame callback.
- Buses: master (trim × fader law × crossfader) and cue/PFL (trim only, pre-fader; `SetPfl`), headphone feed = cue blended to master by `SetCueMix`. `configureOutput(routing, deviceId)` maps them: STEREO (master), SPLIT_MONO (L mono master / R mono cue), QUAD (ch1/2 master, ch3/4 cue; reopens the stream with 4 channels — offer only for devices reporting ≥4 channels, e.g. a DDJ-GRV6). Reconfiguring replaces the stream; engine state survives.
- Output disconnect: Oboe closes the stream; `onErrorAfterClose` opens a replacement (engine state survives). `reopen()` retries a failed recovery; the app service calls it every 2 s while `outputOpen` is false.
- Seeking past the end parks the deck (`atEnd`), not an error.
